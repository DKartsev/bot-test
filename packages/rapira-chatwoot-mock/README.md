# Rapira Chatwoot Mock Integration

Прототип показывает, как подключить пользовательские данные к боту/оператору поддержки Chatwoot через Dashboard Apps и отдельный API для генерации ответа.

Модель данных учитывает активные финансовые операции:

- пополнения: `СБП`, `P2P сделка`, `криптовалюта`, `наличные в офисе`;
- выводы: `P2P`, `криптовалюта`, `наличные в офисе`;
- для активных операций возвращаются сумма, токен, сеть, статус, ID операции и текущее время обработки.
- блок `support` намеренно не возвращается наружу: внутренние флаги и подсказки не должны попадать в интерфейс или клиентский API.

## Запуск

```bash
npm install
npm start
```

Откройте:

```text
http://localhost:8787/dashboard.html
```

## Подключение в Chatwoot

1. Откройте `Settings -> Integrations -> Dashboard apps`.
2. Нажмите `Configure`.
3. Добавьте приложение:
   - Name: `Rapira User Context`
   - URL: `https://your-public-url/dashboard.html`
4. Откройте любой разговор. В панели приложения должны появиться данные клиента.

Chatwoot передает контекст текущего разговора и контакта в iframe через `window.postMessage`.

## API заглушки

Получить данные пользователя:

```http
GET /api/user?email=client@example.com
```

Получить готовый ответ для бота:

```http
POST /api/support-answer
Content-Type: application/json

{
  "question": "Почему не проходит вывод USDT?",
  "contact": {
    "email": "client@example.com"
  }
}
```

## Логика бота

Бот поддержки должен работать по цепочке:

1. Получить вопрос пользователя и идентификатор контакта из Chatwoot.
2. Запросить `GET /api/user` или реальный Rapira API по `email`, `phone`, `user_id`.
3. Сформировать ответ на основе статусов аккаунта.
4. Не раскрывать внутренние поля вроде `risk_level`, технические причины антифрода и приватные служебные заметки.
5. Если есть блокировка, KYC rejected/pending или security hold, отвечать аккуратно и передавать кейс оператору.
